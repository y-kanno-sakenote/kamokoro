# 醸しコロ 仕様 v3（技プール7→4・エネコロカスタム・蔵めぐり／2026-09-03 設計案。実装前）

v2（`docs/spec.md`）は触っていない。**v3が実機で確定してから統合する**。
キャラ定義（HP・固定2面・カスタム4面の初期値・技プール7つ）は **`docs/characters.md` が正**。この文書はルールと数値の枠だけ持つ。

## v3で足すのは3つだけ
1. **技プール7つから4つ選ぶ**（キャラごと。★＝v2の既定4技）
2. **エネコロのカスタム**（6面のうち4面をチップで差し替える）
3. **蔵めぐり**（CPU6体を順に倒す。勝つとチップがもらえる）

## v2から変えないもの（憲法）
- 戦略は「**どの技を狙うか**」だけ。振り直しは無い
- 効果の語彙は5つ（`+N` / `自分にN` / `相手の次エネコロ-1` / `次に受けるダメージ半減` / `回復N`）。**足さない**
- キャラコロは画面で転がる。UIに専門数値（成功率%・日本酒度など）を出さない。二つ名も出さない
- ターンの流れ・しずく5・とくせい「ロマン」・先攻1手目エネコロ2個・前の手番の技は選べない
- 数値は全部叩き台。`sim/` で実測してから確定

## 1. 技プール（7つ→4つ）

- プールの内訳はキャラ共通: **安定（コスト1）×2 ／ 中（2）×2 ／ ロマン（3）×2 ／ 支え（回復か半減）×1**
- 選ぶのは**4つ。区分の縛りは無い**（安定4つでも、ロマン2つ＋中2つでもよい）
- v2の4技はプールにそのまま入っている（名前・コスト・威力・向き・効果を1つも変えていない）。★4つを選べばv2と完全に同じ戦い
- **バトル中は変えられない**。準備画面でだけ組む
- CPUは**常に★の4技**（v2の既定セット）を使う。CPU側にも選ばせない（足さない／v2実測が回帰テストとして生きる）

## 2. エネコロのカスタム（固定2面＋カスタム4面）

- 6面のうち **2面は固定**（そのキャラのコスト1技のエネ×2）。鍵アイコンを出して押せなくする
- 残る **4面がカスタムスロット**。各スロットには「**素の面**」が書いてある（＝v2の面）
- スロットに**チップを1枚はめる**と素の面が隠れる。外すと素の面が戻る。**1面に1枚まで**
- 同じ種類のチップを何枚はめてもよい（在庫がある限り）
- **素の面はチップ在庫に入らない**（外して他キャラに回すことはできない）。回せるのは戦って手に入れたチップだけ
- 装着済みチップは外すと在庫に戻る。キャラ間の付け替えは自由

### チップ一覧（5種・2026-09-03改訂＝2エネチップ廃止）
| チップ | 面の意味 | 出方 |
|---|---|---|
| 🌾 / 🍚 / 💧 / 🔥 | そのエネ1個 | 勝つたび（通常枠） |
| ✨ | 万能1個（どれか1つの代わり） | レア枠 |

**2エネチップ（🌾🌾等）は廃止した**（§7の実測で✨1面まで上限に絞っても80%の目標に届かず、§8案1の「2エネ廃止」を採用。経緯は§7参照）。レアは✨だけになった。

### 2.1 カスタム上限（実装確定・2026-09-03）
- **✨は1ダイスに1面まで**（固定2面は数えない）
- **初期構成の✨1面（各キャラのカスタム4面のうち1つが元から✨）もこの上限に含める**。つまりチップの✨は実質はめられない（すでに1面ぶん使っている）
- 準備画面: 上限に達する置き換えはチップをグレーにして選べなくし、理由を短く出す（「✨は1面まで」）
- 旧セーブが上限を超えている、または廃止済み（2エネ等）のチップを装着していたら、読み込み時に外して素の面へ戻す（上限違反は在庫に返す。廃止済みチップは在庫自体が無いので戻さず消える）
- 実装は `engine.js` の `validateSlots` / `canPlaceChip` / `repairSlots`

## 3. 蔵めぐり（唯一のモード）

- キャラを1体選ぶ。**CPU 6体をランダム順に**1体ずつ倒していく（自分と同じキャラも相手に出る）
- 1戦ごと: 準備 → バトル → 結果 →（つぎへ）→ 準備 …
- **勝つとチップ1枚**。結果画面に「🍚をもらった！」の1行だけ出す（画面は増やさない）
- **3勝ごとにレア1枚**（3勝目・6勝目。通常枠と合わせてその戦は2枚）
- **負けたらその周は終了**。もらったチップは減らない。もう一度最初から（相手順は振り直し）
- 6体倒したら1周クリア。何周でも回せる

### ドロップ表（6面のダイスで決める）
倒した相手の**タイプに寄る**。「寄りエネ」は 🫧泡→🍚 ／ 🌸香→💧。

| 出目 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| **泡に勝った** | 🍚 | 🍚 | 🍚 | 🌾 | 💧 | 🔥 |
| **香に勝った** | 💧 | 💧 | 💧 | 🌾 | 🍚 | 🔥 |

寄りエネ50% ／ 他3種は各16.7%。

### レア表（3勝ごと）
2エネ廃止（2026-09-03）でレアは✨だけになったため、6面のダイスによる抽選は廃止。**3勝目・6勝目は必ず✨1枚**。

1周（6勝）で **通常6枚＋✨2枚**。カスタム4面を全部✨で埋めることはできない（✨は1ダイス1面までの上限があるため。§2.1）。

### 3.1 CPUの周回強化（段2・廃止）
§2.1の上限（当初は✨1面／2エネ2面）内でも「最強構成 vs 初期構成」が80%を超えるキャラが実測で見つかったため、2026-09-03に一度実装したが、実測（`node sim/sim.js 2000 --v3 --laps`、廃止前のコード）で最良キャラ（協会6号）が周回2で94.9%・周回3で96.1%と目標に届かず、**効いていないので削除した**。バトル開始時の「◯周目：相手もレアを◯枚」表示、`engine.js` の `cpuLapChips` も合わせて削除。CPUは常に★4技・素の面のまま（周回による変化なし）。

## 4. 画面（合計4枚。準備を1枚足すだけ）

### ① キャラ選択（v2のまま＋1行）
6枚のカード。上に「蔵めぐり ●●●○○○（3勝）」の1行だけ足す。周の途中ならキャラは固定表示（続きから）。

### ② 準備（**新規**・375×812に収める）
上から順に1画面。
1. **キャラ**（絵文字・名前・HP）1行
2. **技プール7行**（区分ラベル・技名・コスト絵文字・威力・向き→効果）。タップで選択トグル。**4つ選ぶと「たたかう」が押せる**。5つ目は押しても入らない（1つ外してから）
3. **エネコロ6面**（1行）。固定2面は🔒付きで押せない。カスタム4面はタップで**チップ選択シート**が下から出る → 在庫の種類が並ぶ（0枚の種類はグレー）／「はずす」で素の面に戻る
4. **在庫**（1行。`🌾3 🍚1 💧0 🔥2 ✨1` のように絵文字と数だけ）
5. **たたかう**ボタン

- 選んだ4技のコストに **1面も持っていないエネ**が含まれるときだけ、そのエネに小さく⚠️を出す（禁止はしない）
- 数値は威力とコストだけ。**成功率%は出さない**（憲法）

### ③ バトル（v2のまま）
技ボタンは選んだ4つ。面構成の常時表示はカスタム後の6面を出す。

### ④ 結果（v2＋1行）
勝ち/負け・「🍚をもらった！」（レアのときは2枚ぶん）・「蔵めぐり ●●●○○○」・つぎへ／やめる。

## 5. 保存（localStorage）

キー: `kamoshi-koro:v3`（1キーだけ）

```
{
  "v": 3,
  "chips": { "rice":3, "koji":1, "water":0, "heat":2, "wild":1 },   // 未装着の在庫（2026-09-03: 2エネ廃止でチップ5種）
  "dice":  { "k6": [null, "koji", null, "wild"], ... },        // カスタム4スロット。null=素の面
  "moves": { "k6": [0,2,4,6], ... },                          // 選んだ技のプール内index（4つ）
  "run":   { "charId":"k6", "rest":["k9","k14","k7"], "wins":3, "lap":2 }  // 周の途中。無ければ null。lapは1周目=1（旧セーブはlap無し=1扱い）
}
```

- `v` が違う・JSONが壊れている・配列長が合わない → **丸ごと捨てて初期化**（在庫0・素の面・★4技）
- 保存のタイミングは「準備画面のたたかう」「結果画面の表示時」の2箇所だけ

## 6. engine.js への影響（実装は別セッション。ここでは触らない）

- `CHARS[].moves` が7要素になる。`fixed`（固定2面）と`slots`（カスタム4面の素の面）を持たせ、`energy`（6面）は**組み立て結果として作る**
- **面の値が「エネキー」から「エネキーの配列」になる**（`['koji']` / `['wild']`。2エネ廃止前は `['koji','koji']` も存在したが、`matchCost`/`successProb` 側の配列展開コードはそのまま残している＝データ上2エネが出ないだけ）。`successProb` の 6^n 列挙はそのまま使える
- 「次に受けるダメージ半減」を攻撃技の向き効果に使う技が2つある（9号ねかせる・1801ふんばる）。`eff.guard:true` の1キーが要る（**語彙は増えていない**）
- `cpuChoose` は変更なし（★4技しか持たないので）

## 7. simで測る項目（`node sim/sim.js` を拡張）

1. **回帰**: 初期構成（素の面＋★4技）で v2 と同じ36組を回し、v2実測（勝率35〜65%・平均手番6〜10・成功率66%）を**再現するか**。ズレたら実装ミス
2. **技セット総当たり**: 各キャラ C(7,4)=35 通り × 相手6体（★4技・素の面）。勝率が **70%を超える技セット**が無いか
3. **ダイス総当たり**: 技セットを★に固定し、カスタム4面の組み合わせ（5種から重複ありで4枚。✨1面までの上限と面構成の重複を畳むと実際は1キャラあたり50〜60通り前後）× 相手6体。上位を出す
4. **レア最強構成 vs 初期構成**: 3の上位10ダイス × 2の上位10技セット で詰め、**最良構成の勝率が80%以下**か
5. **ドロップ期待値**（乱数不要の計算）: 1周6勝で各チップ何枚たまるか

### 80%超の抑え方・実測結果（2026-09-03、決着）
- **案A（✨と2エネを合わせてレア1面までに縛る）**: `node sim/sim.js 2000 --v3` で実測 → 6号94.6%・7号89.3%・10号91.6%・14号88.9%が80%超で **NG**（9号75.7%・1801号67.3%はOK）。レアを絞っても、通常チップ（🌾🍚💧🔥）だけで4面を技セットに最適な構成へ自由に組み替えられること自体が勝率を押し上げていて、レアの制限だけでは効かないと判明
- **案B（2エネチップを廃止し、レアは✨だけ・✨は1面まで）を採用**: 同条件で再実測 → 6号93.9%・7号88.9%・10号91.8%・14号88.7%と、**案Aとほぼ同じ数値でやはり80%を超える（NG）**。2エネの有無は結果にほぼ影響しておらず、想定していた§7(a)(d)のどちらの対策も単独では目標に届かないことが確定した
- **裁定**: それでも案Bを採用する（実装がいちばん軽く、チップ種を減らせる§8案1の考え方に沿うため）。ただし**6号・7号・10号・14号の4キャラは80%目標を満たせていない**（67〜75%で収まるのは9号・1801号のみ）。原因は主に技セット選択＋通常チップの自由な組み替えそのものにあり、レア（✨）の扱いを変えるだけでは解決しない。次に手を付けるべきは §7(b)(c) のようなレア頻度・表の調整ではなく、**技セットの自由度そのもの**（§8案2の技プール5種化や、カスタム4面の枚数を減らす等）。次のセッションで裁定すること

## 8. 減らす案（併記）

1. **2エネチップを廃止し、レアは✨だけにする**。チップ5種。**2026-09-03採用**（上記の通り、単独では80%目標に届いていないが、実装の単純さを優先して採用）
2. **技プールを7→5に**（安定2・中2・支え1。ロマン枠はv2の1つのまま）＝新技は各キャラ2つ。プール表示が5行になり準備画面が軽い。**未着手。80%目標に届いていない4キャラへの次の一手の最有力候補**
3. **向き効果の「次に受けるダメージ半減」2つを+10に置き換える**。`eff.guard` の実装が不要
4. **チップを廃止し、報酬を「技プールの解放」だけにする**（勝つと新技が1つ開く）。画面は3枚のまま、保存は `moves` と `run` だけ。カスタムの面白さは減るが、いちばん小さいv3
5. **蔵めぐりで負けても続行**（周を持たない）。`run` を保存しなくてよくなり、`chips`と`dice`だけの保存で済む
6. **⚠️（コストのエネを1面も持っていない警告）を出さない**。6面が常に見えているので気づける
